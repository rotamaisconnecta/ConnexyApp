## 4. A geração sobrescreveria a correção?

**Sim, é o comportamento esperado.** O arquivo se declara auto-gerado (`:1`) e a documentação o
descreve como "autogerado e travado". Uma regeneração pela plataforma substituiria integralmente o
corpo do arquivo e removeria as linhas `6` e `39-45`, devolvendo a leitura divergente
(`import.meta.env.VITE_APP_*`).

Agrava o risco: o plano de 2026-08-19 assumia que esses arquivos ficariam **código morto** após
redirecionar os importadores (linhas `:16-17`, `:76-78`). Isso **não se confirmou** para o middleware:
ele tem um importador vivo —

- `src/lib/media/media-url.functions.ts:3`: `import { requireSupabaseAuth } from "@/integrations/supabase/auth-middleware";`

Portanto, regenerar o middleware não afeta código morto: **reintroduz a divergência no caminho vivo da
server function de mídia**, reabrindo o achado M2.

Observação: outros dois arquivos gerados já foram neutralizados por equivalentes próprios — `start.ts:4`
usa `attachAppSupabaseAuth` de `src/lib/supabase/auth-attacher.ts` (repo-owned) e
`media-server-authorization.server.ts:69` importa `client.server` dinamicamente. O middleware, porém,
permaneceu acoplado ao arquivo gerado.
